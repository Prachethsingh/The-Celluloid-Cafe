# Automatic movie playback

Catalog series episodes also use backend discovery. The client supplies the selected episode ID and season/episode numbers; the backend matches the series, loads its provider season's episode list, and resolves only an exact episode match. Unnumbered or ambiguous episode packs are rejected. Episode identities are included in both returned sources and cache keys. Choosing an episode is still required; provider selection is not. Provider-only browser sandbox entries and explicitly connected Stremio add-ons retain their existing client adapters.

Pressing Play uses configured title-specific sources first. If none exist, the web client asks the API to run the original Vega search, metadata and stream modules inside a backend-hosted Chromium sandbox. Disabled providers are excluded. Matching requires an IMDb identity or an exact normalized title and release year. Ambiguous matches, embeds, torrents and streams requiring custom browser-forbidden headers are not selected.

The backend requires the root dependencies (including `@playwright/test`), its Chromium browser installation, the compiled provider modules, and the Vega sandbox build. The existing production Docker image is not provisioned with Chromium: this capability is currently configured for the local full-project runtime. Missing runtime dependencies produce a visible diagnostic, not a fabricated stream.

Eight providers are checked concurrently in the saved priority order, each with an eight-second limit and an overall 35-second discovery deadline. Discovery stops as soon as a provider returns supported sources; other checks are cancelled and unstarted providers are marked not needed. Providers not reached before the deadline are explicitly reported as unchecked/time-limited. Only one discovery job runs per API process; other requests receive a busy response. Results are cached briefly in memory (60 seconds for sources, 15 seconds for failures). Network requests require public IPv4 HTTPS endpoints, pin DNS results, revalidate redirects and limit response size. Native WebView, cookies and unsupported crypto operations report unsupported capability errors.

The v2 provider preference migration clears the previous local disabled list once, enabling all local providers as requested. Subsequent manual opt-outs persist. The workspace provides an Enable all providers action. Upstream-disabled modules remain labelled and excluded from automatic discovery; local enabling does not establish upstream availability. Stremio add-ons still require an explicit add-on connection.

Autoplay next is enabled by default and can be turned off in the player. At movie completion, the player checks later movies in the backend catalog's stable ID order, skips unavailable titles and starts the first one returning a supported source. It does not wrap to the beginning. Closing the player or cancelling autoplay stops the client lookup. Series and provider-only titles do not automatically advance to unrelated movies. Browser autoplay restrictions can still require pressing Play.

Source discovery is not a guarantee of successful decoding or upstream availability. Network/media errors and connection timeouts advance through returned source alternatives; adaptive-engine failures retain the existing manual source selector. No movie is silently replaced when its initial Play request fails.

Validation: `npm test`, `npm run lint`, `npm run build`, and `npm run test:e2e -- e2e/autoplay.spec.js`. Use separate `E2E_API_PORT` and `E2E_WEB_PORT` values when the development services are running. Browser autoplay tests use explicitly mocked source discovery and the local media fixture, not third-party movies.
